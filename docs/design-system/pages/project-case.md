# Project Case Page Overrides

> Applies to both project routes and overrides `../MASTER.md` only where specified.

## Purpose

Prove capability through a readable technical narrative, real interface media, a live demo, and source code. Case Studies do not imitate agency case studies with fabricated client metrics.

## Layout

- Narrative width: 760px.
- Media width: 1200-1440px depending on asset quality.
- Opening metadata includes role, stack summary, demo, and GitHub before the first long narrative section.
- Challenge, solution, defining capabilities, and technical decisions form one compact narrative section rather than separate chapters or a feature list.
- Follow the compact narrative with the ordered media sequence; do not turn the page into a masonry gallery.
- Demo, GitHub, and contact actions remain visible text links or buttons.

## Motion Budget

- Do not carry the Home Page blueprint into Case Studies.
- Opening media may use one clip-path reveal over 600ms with `--ease-in-out`.
- Remaining media uses opacity plus at most 8px translation, once per asset.
- Gallery viewer follows the modal contract in `MASTER.md`.
- Page navigation is immediate; no cinematic route transition.

## Media Rules

- Use 4-6 assets per project, each selected to prove a named capability.
- Preserve source aspect ratios where possible; do not place every screenshot in a device mockup.
- Optimize image sizes and formats; split Case Study code by route.
- Captions explain the decision or interaction shown, not the filename or screen title.

## Credibility Rules

- No certificates, client logo, testimonial, revenue metric, or before/after business result without evidence.
- Link to the public demo and GitHub repository.
- Describe personal projects as projects; do not claim a client engagement and do not foreground their learning context.
